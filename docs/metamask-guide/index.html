Read this first

You are about to put a second account in your MetaMask. Know which one is which.

This guide has you install a browser extension that can also hold real cryptocurrency, and import a private key that anyone on the internet already knows. Both of those are completely safe here — but only if you never lose track of which account is which. Keep this table in mind for the rest of the guide.

✅ The classroom account (fake)

  • Network name reads exactly "PropChain Classroom", chain ID 31337
  • Was added by clicking Import account and pasting a private key that's printed in this project's own README and source code
  • "ETH" and property tokens here were created by a script on a laptop five minutes ago
  • Resets to zero the moment the instructor restarts the Hardhat node
  • Safe to screen-share, screenshot, or post the private key anywhere

🛑 Any other account (potentially real)

  • Any account you created by choosing "I have an existing wallet" or typing in your own 12/24-word recovery phrase
  • Any network named Ethereum Mainnet, a real L2 (Base, Arbitrum, Polygon…), or a public testnet
  • Anything you'd use to buy, hold, or receive real crypto, even "just a little"
  • Never paste a private key you don't fully recognize into this account, and never export this account's own private key to anyone
The one rule that matters: the private keys you'll import in this guide are intentionally public — they're Hardhat's well-known default test keys, documented on Hardhat's own site and reused by every Hardhat project in the world. That's exactly why they must never hold anything real: if you ever sent real funds to one of these addresses on a real network, anyone could take it instantly. Going the other direction is just as important — never import your own real wallet's seed phrase or private key into anything related to this classroom exercise.

1 · Install

Install the MetaMask browser extension

MetaMask is a browser extension, not a separate app — install it from your browser's own extension store so you get a copy that's verified by Microsoft/Google, not a copy from a random download link.

  1. Edge: open edge://extensions (or search "MetaMask" directly in the Microsoft Edge Add-ons store) → Get → Add extension.
    Chrome: open the Chrome Web Store → search "MetaMask" → Add to Chrome.
  2. Pin it to the toolbar (the puzzle-piece icon → pin) so you can get to it in one click.
  3. Click the new fox icon to open it for the first time.
2 · New wallet or existing?

Choose "Create a new wallet" — even if you already use MetaMask elsewhere

MetaMask's very first screen asks you to create a new wallet or import an existing one. For this classroom exercise the answer is always Create a new wallet, for one simple reason: there is no good reason to mix a throwaway teaching wallet with anything that might hold real value, even though the specific key you'll add later carries zero risk to your other accounts.

  1. Click Create a new wallet (not "I have an existing wallet").
  2. Agree to terms, then set a password — this only encrypts the extension on this device; it has nothing to do with the classroom account.
  3. MetaMask shows a 12-word Secret Recovery Phrase for this new, empty wallet. You can skip "secure it now" — this wallet will hold nothing of value, so there's nothing at stake in that phrase. (If you ever do fund this wallet for real later, go back and back up that phrase properly then.)
  4. You'll land on the main MetaMask screen with one auto-generated account holding 0 ETH. Ignore it — the next section adds the account you'll actually use.
If you already use MetaMask for real crypto in this browser: good news, you can still safely import the classroom test account as an additional account inside your existing wallet — importing a key only adds an account, it never touches your existing ones. Just be extra careful in step 3 to pick the account you actually want active before connecting it to this app, so you never approve a transaction from the wrong one.
3 · Import the test account

Import a Hardhat test account by private key

The app itself hands you these keys — open the classroom link (your instructor's URL, or http://localhost:5173) and look for the Student Quickstart panel near the top. Each of the 10 cards there has a Copy private key button. Copy the one for your assigned account (e.g. "Student 1").

Example — Student 1

Address: 0x70997970C51812dc3A010C7d01b50e0d17dc79C8
This exact address, and its private key, are printed in this project's own README.md and frontend/src/hardhatTestAccounts.js. Everyone running this project sees the identical 10 accounts — that's expected, and is exactly why they must stay fake forever.

Newer MetaMask versions (the ones that also support Bitcoin/Solana/Tron addresses per account) renamed the button and moved it — if your menu doesn't say "Import account" where you expect it, use this exact path instead of guessing:

  1. Click the account selector at the top of the wallet (shows your current account name).
  2. At the bottom of that list, click "Add wallet" — not "Add account," which just creates another empty account under your existing wallet.
  3. On the next screen, under the "Add wallet" options, click "Import an account."
  4. Paste the private key you copied → click Import.
The imported account shows up as a brand-new entry in the account selector. Select it as the active account before moving to the next section — the app connects to whichever account is currently active in MetaMask, not whichever one you imported most recently.
4 · Connect & buy

Connect the wallet and complete a real transaction

  1. With the imported account active, open the classroom app link and click Connect Wallet.
  2. MetaMask asks which account to share — pick the imported one → Next → Connect.
  3. You'll likely see an "unverified network" or "review alert" warning next. This is expected: chain ID 31337 isn't a public, "verified" network, and the app's URL is a randomly-named Cloudflare tunnel, so MetaMask can't check either one against its known-safe list. Expand/review the alert and click through it (Connect anyway) — safe here per the Real vs. fake box above.
  4. A network add/switch prompt follows (adding "PropChain Classroom") → Approve → Switch.
  5. Back in the app, confirm the status line shows you're connected at chain 31337.
  6. Scroll to "02 · PRIMARY MARKET — Buy fractional tokens," pick a property, enter a whole-number quantity, and click "Approve & buy tokens."
  7. Confirm the two MetaMask popups that follow (an approve, then the actual purchase). The Live Teaching Console at the top of the app narrates each step as it happens — clicked, signed, submitted, mined, confirmed, balances updated.
If step 7 never shows a MetaMask popup at all and the app reports could not coalesce error or MetaMask reports error code 4100 ("account and/or method has not been authorized"), see Troubleshooting below — this was a real MetaMask bug this guide's own test run hit, and the app has since been patched to work around it automatically.
5 · Verify

See the balance inside MetaMask itself, not just the app

The app tracks your token balances on its own, but MetaMask won't display a custom token until you add it manually — it has no way to discover tokens on a private, unverified network by itself.

  1. Make sure MetaMask is on the PropChain Classroom network with your imported account active.
  2. Open the Tokens tab in MetaMask → Import tokens (older versions call this Manage tokens).
  3. Switch to Custom token and paste the property token's contract address — the app's deployment.json lists one per property (e.g. Dallas Garden Apartments / DGA).
  4. Symbol and decimals (18) should auto-fill. Click Import.
A quick sanity check worth doing once: buy 10 tokens, check the balance shows 10 in MetaMask; buy 10 more, confirm it reads 20. If the app's own balance and MetaMask's imported-token balance ever disagree, trust MetaMask's (the app re-reads from the chain on refresh, so a stale app view usually just means the page needs a reload).

What changed in the app to make remote testing possible

Student Quickstart panel

All 10 Hardhat test accounts, with one-click "copy private key" buttons, right in the app — a remote student never needs to see the instructor's terminal output.

?rpc= link override

The frontend and the Hardhat RPC node get two independent Cloudflare tunnel hostnames when testing remotely — not "same host, different port" like a LAN. The instructor's panel builds one shareable link that carries both.

Token ownership map

A live, area-proportional bubble chart of who holds what, built from real on-chain Transfer events — the same technique a real block explorer uses, not a hardcoded guest list.

One-script start/stop

startPropChain.bat / .sh (--tunnel flag) brings up the node, deploys, starts the frontend, and opens both Cloudflare tunnels in one command — printing the exact shareable student link at the end. stopPropChain.bat / .sh tears it all down.

Automatic permission re-grant

ensureNetwork() now re-requests account permission once, right after adding the custom network, working around a real MetaMask regression (see Troubleshooting) that used to silently block every transaction.

Troubleshooting

Problems this guide's own test run actually hit

"Connect Wallet" does nothing

Almost always means MetaMask isn't installed in this specific browser yet (a different browser on the same computer doesn't count). Install it per step 1, then reload the page.

No "Import account" option anywhere

Newer multichain MetaMask builds renamed this flow — use account selector → "Add wallet" → "Import an account" exactly as in step 3, not "Add account" (which just creates another blank account) and not an individual account's "Account details" screen (which is for exporting that account's own key, not importing a new one).

Clicking buy shows nothing, then could not coalesce error / MetaMask code 4100

This is a real MetaMask regression (v13.55+): adding a custom network via wallet_addEthereumChain doesn't always re-scope an already-connected account to that new chain. eth_accounts still reports the account correctly, but eth_sendTransaction silently gets rejected — no popup appears at all, because MetaMask refuses before it ever shows one.

This is now fixed automatically in the app (ensureNetwork() re-requests account permission once after the network is added). If you're on an older cached version of the page, or still see this, run the fix manually once in the browser DevTools console (F12 → Console) while the app tab is open:

await window.ethereum.request({method:'wallet_requestPermissions', params:[{eth_accounts:{}}]})

Approve the popup it shows, then retry the action.

"Review alert" / "Continue at your own risk" warnings

Expected every time, not a sign of an actual problem — MetaMask can't verify an unrecognized chain ID (31337) paired with a randomly-named tunnel domain against its known-safe list, so it flags the combination generically. Safe to proceed given the account in use is a disposable Hardhat test key (see Real vs. fake).
